# Seedance 影视创作流水线

以“人物与因果先成立，再决定怎么拍，最后编译”为核心。完整项目使用生产门禁；单点专科只处理用户指定范围，不强迫进入整条流水线。镜头数、节奏点和字段模板不能反过来支配故事。

## 先选择任务模式

开始时只选择一个模式并写入 `task_mode`：

- `full_production`：从故事、剧本或素材推进完整生产包，执行 S0–S10 和 G1–G7。
- `specialist`：用户明确要求剧本会诊、对白精修、平台节奏体检或后期声音设计，只读取对应参考文件。

不要因为用户粘贴了剧本就自动改写。任务不清楚但已有可执行的单点要求时，先完成该单点；只有选择会改变故事、授权范围或交付物时才追问。

## 创作门禁不等于协作确认表

G1–G7 只管理用户与影视创作智能体之间的内容锁定：剧本、分镜、资产和最终编译是否可以进入下一阶段。它们不是制片团队的视频协作确认表，也不替代 Google 表格。

本 Skill 不定义或维护负责人、审核人、意见汇总、A/B 类修改、云端初版验收、水印/无水印交付、发布日期、Google Sheet 行列或团队完成状态。这些属于外部协作 SOP 或表格。用户提供协作表时，只读取其中明确批准且与当前创作有关的事实；除非用户明确要求操作该表格，否则不复制表结构、不回写状态、不把协作字段加入项目状态模板。

## 不可破坏的规则

1. 用户确认内容和原始素材事实是 Canon，不得静默改写。
2. 剧本、分镜、资产和最终提示词使用稳定 ID 与明确 revision。
3. 下游只读取当前 revision 已批准的上游产物，不凭记忆重新概括。
4. Seedance 编译只能转换已批准内容，不新增剧情、人物、能力、道具或结局。
5. 改变锁定事实时先写变更单并按影响范围回退门禁。
6. 没有真实且已验收的附件，不得写 `@图片N`、`@视频N`、`@音频N`。
7. 自检通过不等于用户确认；“继续”只批准唯一正在等待的门禁。
8. 镜头数是创作结果，不是目标或验收指标；没有新的观看理由就不切镜。
9. 默认保留人物的含混、停顿、失败动作和不对称节奏，不把每句台词、每个表情都加工成完整戏剧功能。

## 默认生产参数

- 中文、16:9；参考素材画风优先，无参考时默认电影写实。
- 单次生成时长由已批准的戏剧单元决定，不超过当前入口上限；没有用户时长要求时，先完成戏再估算，不默认填满 30 秒。
- 文戏、武戏均使用“最少充分镜头”：长镜头、少切镜或高密度剪辑都可成立，但每次切镜必须带来新的空间、信息、关系、动作或感知价值。
- 4×4、16 镜只在用户明确要求该故事板版式，或当前段确实适合高密度动作设计时启用，不作为默认生产规格。
- 默认使用对白、OS、环境声和同步音效；BGM 只在剧情或用户明确需要时加入。
- 默认避免血腥、肢解、开放伤口和伤口特写。
- Seedance 2.5 官方能力上限为单次 30 秒、30 张图片、10 段视频、10 段音频；实际产品入口更低时服从当前界面。

## 完整生产模式

完整项目按以下门禁逐轮推进，不在一轮内从剧本冲到最终提示词：

1. `G1 script_adaptation`：来源锁定、问题诊断、完整 AI 可生成剧本、改编说明与待确认假设。
2. `G2 shot_breakdown`：项目圣经、文/武分段、连续文字分镜与跨段状态。
3. `G3 asset_prompts`：固定资产清单、稳定 ID 与可直接复制的自然语言提示词。
4. `G4 character_look`：每名主要角色一张横向四栏定妆基准图；实际看图后等待确认。
5. `G5 asset_images`：场景、道具、武器和 VFX 分批生成、看图与确认。
6. `G6 storyboard`：按已批准分镜和资产生成故事板/关键帧，实际验收后确认。
7. `G7 final_compile`：绑定真实引用，输出 Seedance 2.5 分段提示词。

只有用户明确说“全自动并放弃中途确认”才可连续推进；仍须保存每阶段状态、执行视觉验收并运行校验。完整阶段规则读取 [references/workflow.md](references/workflow.md)。

## 单点专科模式

- **剧本会诊**：读取 [references/review-dialogue.md](references/review-dialogue.md) 的“剧本会诊”。只诊断时不改变 Canon；应用修改时提升 revision，并重新打开 G1–G7。
- **对白精修**：读取同一文件的“对白精修”。默认只改有明确病灶的台词，保留锁定台词；应用修改时按剧本变更处理。
- **平台节奏体检**：读取 [references/platform-rhythm.md](references/platform-rhythm.md)。诊断不改 Canon；应用新的节奏档位时提升 revision，并重新打开 G1–G7。
- **后期声音设计**：读取 [references/post-sound.md](references/post-sound.md)。独立 Cue Sheet 不改变 Canon；若改固定对白或 Seedance 内声音指令，只重新打开 G7。

专科任务不得创建无关资产或门禁，也不得用虚构专家身份、假履历或角色扮演代替证据。

## 交互状态卡

每次阶段或专科交付末尾都输出一张短卡，不重复正文：

```text
【交互状态】
模式：完整生产 / 单点专科｜项目：PROJECT-ID｜revision：N
当前阶段：Sx / 专科类型
等待确认：门禁名 / 无
本次确认范围：具体产物或目标场次
可选操作：通过｜修改……｜仅诊断不应用｜停止
若修改将失效：门禁列表 / 无
下一步：交付物与所需材料
```

发出确认问题后停止。用户要求修改时留在当前阶段，重发完整阶段成品后再次等待。

## 项目状态与 Canon

有工作目录时，从 `assets/project-state.template.json` 建立项目状态；没有文件工作流时在回复中维护等价台账。至少维护：

- `SOURCE_LOCK`：原始事实、不可改项、允许补足项。
- `SCRIPT_LOCK`：已确认剧本、场次、建议补足与假设。
- `CHARACTER_LOCK`：身份、外观、声线与语言指纹。
- `ASSET_MANIFEST`：资产 ID、版本、状态、真实附件、职责与禁止覆盖项。
- `SEGMENT_LEDGER`：模式、目标时长与理由、戏剧/战术单元、核心变化、起止状态、节奏档位、镜头数与切镜理由。
- `SHOT_LEDGER`：时间、主体、动作/表演、声音、结束状态和资产 ID。

台账字段未知时明确写“未知/待确认/待生成”，不得补造。进入下游前核对人物、关系、台词、胜负、资产版本、左右手、道具数量、场景破坏、光向、声音尾部和跨段状态；发现差异时停止编译并回退责任阶段。

## 资产和视觉验收

- 资产提示词对外必须是可直接投喂的自然语言成品，不以标签清单代替。
- 人物定妆固定为同一张横向四栏图：正面半身面部近景、全身正面、全身 90 度标准侧面、全身背面；同一人物、妆发、服装、材质、尺度、基线和光线。
- 有生成工具且当前资产提示词已确认时才生成；生成后必须查看真实像素。
- 没有工具时只交付提示词和待绑定清单，不声称已生成或已通过。
- 最终提示词只绑定当前 revision 已验收资产；草稿、失败图、旧版图不得进入正式引用。

## 修改与回退

- 只读诊断不改变项目 revision 或批准状态。
- 应用剧本、对白或节奏修改：revision 加一，G1–G7 设为 `pending`，重新确认来源与剧本。
- 修改局部镜头：回退 G2，重算整个片段时间和连续性。
- 修改资产外观：提升资产版本，回退相应资产门禁并重验所有引用镜头。
- 独立后期声音方案不回退；改变固定对白或 Seedance 内声音指令时仅将 G7 设为 `pending`。

每次变化记录原因、旧值、新值、影响范围和需重验项目。

## 机械校验与结束标准

有状态文件时运行：

```text
python scripts/validate_project_state.py <project-state.json>
```

脚本通过只证明结构、门禁、平台时长上限、时间连续、编号和引用满足约束；它不评价镜头多寡，也不证明剧情、表演和文字自然。完成前必须再做一次“删除模板痕迹”人工复核：若换一组角色名仍基本成立，说明文本不够具体，必须重写。
